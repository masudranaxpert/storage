## 1. Problem Statement & Motivation

The user wants custom control over their commodity VPS pool:
1. **Edge/Node Processing:** Workers must actively download, remux, and process files on the node itself rather than acting as passive object storage.
2. **Strict Quota Enforcement:** Nodes must strictly respect admin-allocated storage boundaries (`AllocatedMaxBytes` / `QuotaBytes`) and never exceed their allocation, regardless of host disk size.
3. **Self-Contained Worker Packaging:** Eliminate slow, fragile `apt-get install` commands on remote VPS nodes by packaging the worker agent along with static binaries of `aria2c`, `ffmpeg`, and `rclone` into a single unified deployment artifact.
4. **Codebase Modularization:** Deconstruct the 1,954-line God Object (`pkg/cluster/agent.go`) into clean, deep modules with explicit seams according to `/codebase-design`.

## 2. Architectural Design & Seams (`codebase-design`)

### 2.1 The New Worker Packaging Model (`/opt/stream`)
Instead of running `apt-get install aria2 ffmpeg rclone` at runtime over SSH:
* **The Bundle Artifact:** `stream-bundle-linux-amd64.tar.gz` (generated by `make bundle` or coordinator on demand).
* **Bundle Contents:**
  ```text
  /opt/stream/
  ├── bin/
  │   ├── stream        (Worker agent binary)
  │   ├── aria2c        (Static standalone binary)
  │   ├── ffmpeg        (Static build with web codecs)
  │   └── rclone        (Static standalone binary)
  ├── etc/
  │   └── config.json   (Node identity, coordinator target, secret)
  └── data/
      ├── media/        (Allocated storage space)
      └── processing/   (Isolated scratch space)
  ```
* **Benefits:**
  * Provisioning drops from 2 minutes of unstable `apt-get` to 3 seconds of curling and unpacking a single tarball.
  * Zero OS distro lock-in (runs on Ubuntu, Debian, Alpine, Rocky, Arch).
  * Worker runs under an unprivileged `stream` service user, not `root`.

### 2.2 Decomposition of `pkg/cluster/agent.go` (1,954 lines -> Focused Modules)
Split the monolithic agent into deep, single-responsibility components:
* `pkg/cluster/agent/agent.go`: Lifecycle, config, graceful start/stop (<200 lines).
* `pkg/cluster/agent/grpc_client.go`: gRPC control-plane stream to coordinator (<250 lines).
* `pkg/cluster/agent/quota.go`: Storage quota tracker & pre-flight write guard (<150 lines).
* `pkg/cluster/agent/server.go`: Authenticated HTTP API & range streaming (<250 lines).
* `pkg/cluster/agent/transfer.go`: Consolidated node-to-node transfer engine (<300 lines).

### 2.3 Strict Quota & Allocation Guard
Before accepting any file ingest, download, or transfer:
```go
// Pre-flight quota check on worker before allocating space
func (q *QuotaGuard) Reserve(incomingBytes uint64) error {
    q.mu.Lock()
    defer q.mu.Unlock()
    if q.usedBytes + incomingBytes > q.allocatedMaxBytes {
        return ErrQuotaExceeded
    }
    q.usedBytes += incomingBytes
    return nil
}
```
* If a node is allocated 100 GB, writes hard-stop at 100 GB.
* No silent deletion of user files. If a tier or node is full, return HTTP 507 Insufficient Storage or fail over to an overflow tier cleanly.

### 2.4 Unified Control Plane (Eliminate Competing Seams)
* **Single Seam:** Coordinator <-> Agent communication flows over the **authenticated gRPC bidirectional stream (`/cluster.Mesh/NodeChannel`)**.
  * Upstream: Telemetry heartbeats (every 5s), job progress reports, quota updates.
  * Downstream: Job dispatches, cancel signals, upgrade instructions.
* **HTTP on Agent (Port 2052):** Used **only** for authenticated file transfers and streaming video to viewers. Protected by shared cluster secret (`X-Cluster-Secret` / Bearer token).

### 2.5 Consolidated Node-to-Node Transfer Engine
* Retire the 3 competing methods (raw chunk map, tar stream, and external rclone rcd over WebDAV).
* Settle on **One High-Speed Engine**:
  * Direct parallel chunked streaming over HTTP with authenticated tokens and strict file bounds.
  * SHA-256 manifest verification on completion.
  * Delete `pkg/cluster/transfer_native_backup.go` (402 lines of dead code).

## 3. Scope & Non-Scope

### In Scope
1. Refactoring `pkg/cluster` into clean deep modules.
2. Self-contained bundle packaging pipeline for `stream` + `aria2c` + `ffmpeg` + `rclone`.
3. Strict quota enforcement engine on worker agents and coordinator tier scheduler.
4. Security hardening of agent HTTP endpoints (mandatory auth, path traversal fix).
5. Removal of dead code (`transfer_native_backup.go`).

### Out of Scope (Deferred)
* Adaptive bitrate HLS/DASH video ladder generation (deferred until core cluster/storage is solid).
* Web frontend UI redesign (dashboard stays functional with existing views).
